# ADR-0003：Agent 记忆采用「同库 pgvector + 可替换的本地哈希向量」

- 状态：已接受（Accepted）
- 日期：2026-10-28
- 相关文件：`services/api/migrations/versions/0007_agent_memory.py`、`app/models/memory.py`、`app/services/memory_service.py`
- 相关需求：M2（Agent 记忆与复盘）

## 背景

设计文档第 9 章要求三层记忆（事实/过程/情景）**落在同一个 PostgreSQL 事务边界内**，并支持
混合检索（关键词 + 语义 + RRF + 时间衰减）。当时的备选是独立向量库，但那会引入
"业务行已提交、向量写失败"的脏记忆，以及跨系统删除/失效的一致性问题。

同时，本地开发与验收默认 `GBT_LLM_PROVIDER=stub`，没有可用的 embedding 服务。

## 决策

1. **向量列与业务行同库**：`trip_memory_summaries.embedding vector(256)`，与摘要、决策、待办、
   教训在同一张表、同一事务里写入与失效。
2. **默认向量由确定性哈希生成**：`embed_text` 用"拉丁词 + 中文字 + 中文二元组"切分，SHA-256
   投影到 256 维并 L2 归一化。它不具备真实语义泛化能力，但同词/同字必然同维度，足以支撑
   混合检索链路与 P95 验证。
3. **可替换**：接入真实 embedding 只需替换 `embed_text` 并回填；表结构、检索、失效逻辑不变。
4. **检索只读 `valid_until IS NULL`**；历史版本保留用于审计与复盘。
5. **记忆不参与可行性**：复盘摘要只作为下一次规划的上下文，可行性仍由求解器 + 验证器决定
   （设计 §9.5）。

## 后果

- 好处：写入原子、删除/失效一致、无需额外运维组件；测试完全离线可重放。
- 代价：哈希向量召回质量低于真实 embedding；已通过"关键词 + 向量 + RRF"缓解，并在文档与
  验收中明确标注，不把哈希向量伪装成语义模型的输出。
