# ADR-0040：跨研究答案版本的原子主张谱系

- 状态：已接受
- 日期：2026-11-22
- 关联：ADR-0039；市场情报引擎 H2.8
- Supersedes：ADR-0039 的同一答案内版本链实现边界；不改变其证据核验规则

## 背景

主张核验以一个不可变的研究答案版本为输入。此前 claim_key 虽然由规范化陈述、主张类型和 scope 计算，但版本号和 supersedes_id 的数据库约束仍限定在同一 answer_id 内。相同研究问题在新一轮研究中得到相同事实陈述时，系统因此无法把它们识别为同一条事实谱系，也无法清晰比较旧结论与新证据。

## 决策

1. **精确指纹才合并谱系**：只有规范化 statement、claim_type 和 scope 产生完全相同的 SHA-256 claim_key，才进入同一 claim_lineage_id。系统不使用 LLM 模糊语义匹配，不将相似措辞自动合并。
2. **谱系跨答案版本**：claim_lineage_id 在同一 Workspace 内对应一个精确 claim_key；版本号在该谱系内单调递增。每个 Claim 仍保留自身 answer_id、verification run、AgentRun 和 Evidence 快照。
3. **只追加新版本**：新答案产生相同 claim_key 时追加 Claim 版本，并指向上一版本。既有主张内容与 Evidence 关系仍不可变。
4. **待审核期间保留现行采纳结论**：生成新版本不会自动撤销此前 ACCEPTED 版本。旧版本仍是当前人工采纳结论，直到管理员明确采纳新版本；新版本通过人工采纳后，旧 ACCEPTED 版本才转为 SUPERSEDED。
5. **唯一当前采纳版本**：数据库部分唯一索引保证每个 Workspace 的精确主张谱系最多一个 ACCEPTED 版本。人工采纳在 Workspace 锁保护下完成，避免两个答案版本并发接受。
6. **历史只读**：新增只读谱系历史 API；按版本升序返回每个版本的审核状态、核验 verdict、来源证据快照和人工审查说明。
7. **研究计划只评估每条谱系的最新版本**：来源核验计划不重复统计一条主张的全部历史版本；完整历史由专门的 lineage endpoint 获取。
8. **既有数据迁移**：历史记录按 Workspace + claim_key 聚类回填 lineage_id，按创建顺序重排谱系版本并补齐跨答案 supersedes 链；若历史上存在多个 ACCEPTED 版本，只保留最近一次审核的版本为 ACCEPTED，其余标记 SUPERSEDED，审核人、时间与说明完整保留。

## 后果

- 同一事实在多次研究中的证据更新可被追踪，而不同研究答案之间不再形成孤立版本。
- 旧版已采纳事实在新版待审核期间继续有效；系统不会因自动研究而悄悄改变用户已接受的结论。
- 精确指纹策略偏保守：模型仅改变措辞时暂不自动归并；后续可在人工确认机制成熟后增加候选语义匹配，但不可静默合并事实谱系。
- Claim 仍是带有证据快照的暂定结论，不是对来源真实性或独立性的机器认证。
