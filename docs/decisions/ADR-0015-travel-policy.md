# ADR-0015：差旅政策用确定性规则，严格模式阻断激活

- 状态：已接受（Accepted）
- 日期：2026-10-28
- 相关文件：迁移 `0020_travel_policies`、`app/models/policies.py`、`app/services/policy_service.py`、`app/api/routes/policies.py`、`plan_change_service.py`
- 相关需求：PRD 企业协作/费用方向

## 背景

企业差旅政策必须可核对，不能由 LLM 判断"是否合规"。同时"违规"有两种处理方式：提示（建议）
和阻断（制度）。如果只做提示，严格企业的场景无法使用；如果默认阻断，又会破坏现有 MVP 流程。

## 决策

1. 政策规则限定为可确定比较的四类：预算上限、计划费用上限、最少提前预订天数、允许目的国。
2. 评估结果显式列出违规码与细节；币种不一致、预算缺失、计划费用未知都作为独立违规码，
   不默认合规、不猜汇率。
3. 计划生成时把违规快照写入 `plan_versions.policy_violations`，UI/API 可直接展示。
4. 政策 `strict=true` 时激活阶段重新评估并返回 409 `POLICY_VIOLATION`；非严格政策只提示。
5. 政策由 ADMIN 维护；同一时刻使用最新启用政策。

## 后果

- 好处：合规结论可解释、可测试；严格/建议两种制度可切换。
- 代价：规则类型目前有限；复杂审批矩阵与差旅例外流程仍需扩展。
