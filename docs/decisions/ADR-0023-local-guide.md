# ADR-0023：当地指南用离线目录按行程组装，实时源缺口显式标注

- 状态：已接受（Accepted）
- 日期：2026-10-29
- 相关文件：`app/data/local_guide_catalog.json`、`app/services/local_guide_service.py`、`app/api/routes/local_guide.py`、iOS `LocalGuideView`
- 相关需求：PRD 方向五「AI 当地生活与文化助手」、五个核心问题之 8

## 背景

PRD 要求根据即将前往的国家和城市，提前准备商务礼仪、用餐、支付、交通、网络、治安、
常用表达等指南，并**与当天行程结合**，而不是让用户读一份长篇攻略。真正的"个性化推荐"
（餐厅、景点、实时天气）依赖外部数据源；本地没有这些源时，编造推荐比没有推荐更糟。

## 决策

1. **离线目录**：`data/local_guide_catalog.json` 按国家组织 7 类固定条目（礼仪/用餐/支付/
   交通/网络/治安/常用表达），另附重点城市贴士；与签证目录同一套路（可版本化、可评审、不联网）。
2. `GET /v1/trips/{trip_id}/local-guide` 按出行 `countries` 组装国家级条目，城市贴士只返回
   拜访地点 `city` 实际命中的城市——指南随行程裁剪，不整篇铺开。
3. 未接入的能力用 `data_gaps` 显式返回：`LIVE_POI_NOT_CONNECTED`（餐厅/景点推荐）、
   `WEATHER_NOT_CONNECTED`（天气）、`COUNTRY_GUIDE_MISSING`（目录暂无该国条目）。
4. 只读接口，不写库不建任务；与签证/汇率一样，未来接真实源时写入同一目录结构并保留来源。

## 后果

- 好处：方向五从零到一可用；内容确定性可测；缺口可见，不会把"未接入"当"没有风险"。
- 代价：条目是通用商务常识而非实时个性化；城市贴士需随目录维护；"前一天晚上结合次日行程
  推送"属主动式范畴，需后续接建议/通知链路。
