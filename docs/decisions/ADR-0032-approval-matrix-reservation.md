# ADR-0032 审批策略向「矩阵 + 审批链」演进的预留设计

- 状态：提议（Proposed，2026-11-12）——**未实施**；触发条件见文末
- 前置：ADR-0008（风险等级→最低角色）、ADR-0016（多人会签）
- 对应需求：设计评审 N1「审批矩阵抽象」（RICE=4，明确不在 MVP-1）

## 背景

现行审批策略已经是**单步矩阵**：`approval_policies` 以
`(organization_id, subject_type, min_severity)` 为键，映射到
`(required_role, required_approvals)`——即"哪类建议、风险多高 ⇒ 需要什么角色、
几个人会签"。ADR-0016 补齐了会签计数语义。

尚未表达的企业需求是**多级审批链**（如：直线经理 → 财务 → 总监依次批准，
每级可各有角色与人数）。设计评审将其列为 N1（RICE=4，最低优先级），
"为后续企业多级审批预留抽象"。本 ADR 把"预留"落成文字，防止未来实施时
破坏既有约束，同时不在当前批次投入实现。

## 预留设计（实施时遵循，现在不做）

1. **矩阵键不变**。未来扩展只发生在值一侧：`approval_policies` 增加
   `chain jsonb NULL`——形如 `[{"role": "ADMIN", "count": 1}, {"role": "OWNER", "count": 2}]`
   的**有序级次**。`chain IS NULL` 时保持现行为（单级：`required_role` +
   `required_approvals`），两者互斥由 CHECK 约束表达；迁移不可变原则不破坏。
2. **`approvals` 表不动结构基础**。它已按"对象 × 审批人"存决策（ADR-0016 的
   部分唯一索引）。实施多级时只加 `stage integer NOT NULL DEFAULT 1`：
   第 k 级未达阈值前，第 k+1 级不可批准（服务端强制，客户端 Today 显示
   "等待上一级"）。
3. **匹配语义不变**。命中规则保持"同组织内最高 `min_severity` 且 enabled"；
   矩阵只是值的形状从标量变向量。
4. **执行语义不变**。全部级次达阈值才创建 `ExternalAction` 与 EXECUTED 审计
   （沿用 ADR-0016 第 4 条），人审门槛（不变量 I3）不放宽。

## 显式不预留（避免过度设计）

- 跨组织/委托审批（审批人是外组织成员）——与 RLS 租户模型冲突，出现时另立 ADR；
- 按金额区间的审批矩阵——费用/报销审批已走独立路径（`expense_reports`），
  不并入建议审批矩阵；
- 审批链的条件分支/会签否决——真实租户需求出现前不建模型。

## 触发条件

出现第一个需要**三级或以上**审批链的真实租户需求时立项实施；
届时本 ADR 置为「已接受」并补迁移与测试计划。在那之前，
`required_role + required_approvals` 的单步矩阵就是全部实现。
