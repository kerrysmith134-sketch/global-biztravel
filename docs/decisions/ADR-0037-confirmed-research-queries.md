# ADR-0037：研究检索只执行用户确认的查询

- 状态：已接受
- 日期：2026-11-21

## 背景

通用商务出行应用的 Research Planner 可以根据任何用户输入生成检索草案，但模型生成的查询可能过宽、存在实体歧义或不符合用户的实际意图。将模型草案直接送往公网搜索不满足用户控制、隐私最小化和可审计要求。研究能力也不能预设行业、国家、客户类型或固定来源站点。

## 决策

1. 研究规划与研究执行分离。生成 ResearchPlan 不产生外部网络请求。
2. iOS 将搜索查询呈现为可编辑文本，一行一条；用户可以修改、删除或增加查询。
3. 用户点击“确认查询并开始检索”时，客户端将最终查询列表提交到执行 API。服务端规范化、去重、校验数量/长度，并把确切查询与 SHA-256 摘要保存在 WorkflowInstance。
4. 后台 Job 同时保存查询摘要；Worker 在执行前校验 Job 摘要、工作流摘要和实际查询列表一致，只能执行该列表，不回退到模型最初的 query draft。
5. 同一计划的入队去重键包含确认查询摘要。相同查询不会重复创建在途 Job；查询修改后属于新的执行意图。
6. 搜索 Provider 通过配置注入，默认 unavailable。第一版支持部署者显式配置 SearXNG；未配置时 API 返回 503，不入队、不伪造来源。
7. SearXNG 返回的标题和摘要只登记为 `WEB_SEARCH_RESULT`，状态为 `UNVERIFIED_SEARCH_RESULT`。来源 URL、Provider、引擎、原始查询、可用的发布时间及采集时间一并保留。搜索摘要不能作为事实核验结果。
8. Search Provider 只接受 HTTP(S) 来源 URL；不自动抓取结果页面、不执行网页脚本，也不将结果内容里的指令作为系统指令。
9. 复用 `BackgroundJob` 的租约、重试、恢复机制，以及 `WorkflowInstance`、`AgentRun` 和 `Evidence`，不新增重复的研究任务/证据表。

## 后果

- 用户能够在外呼前检查实际会发送的搜索词，降低错误检索和意外扩大范围的风险。
- 查询列表、哈希、Job、执行器审计和证据条目形成可追溯链路。
- Provider 默认关闭，部署者需要配置搜索服务并运行 Worker；没有搜索配置时功能以明确状态失败。
- 本阶段仅完成来源采集。网页全文抓取、事实级引用、来源质量评分、跨来源矛盾检测和研究结论生成仍属于后续能力，不得显示为已完成。
