# ADR-0048：预约窗口必须同时满足 IANA 时区与 UTC offset

## 状态

已接受

## 背景

预约恢复重评请求中的客户窗口同时携带带 offset 的 `start_at`、`end_at` 与 IANA `timezone`。仅验证时区名称存在并不足够：例如 `Europe/Berlin` 与 `+00:00` 可以同时是合法字符串，但在冬季并不表示同一当地时间。若两者不一致，服务端虽然保存了一个确定的瞬间，却会让客户端按另一个时区解释，形成不可审计的预约窗口歧义。

## 决策

1. `start_at` 与 `end_at` 必须是带明确 UTC offset 的时间戳。
2. `timezone` 必须是有效 IANA 时区标识。
3. 服务端分别将两个时间戳转换到该 IANA 时区，并核对转换后的 UTC offset 与输入 offset 一致。
4. 两个端点分别核验，以支持跨夏令时切换的合法预约窗口；不得假设一个窗口只有一个固定 offset。
5. 不静默修正或重新解释客户端时间。出现 offset 不匹配、DST 不存在的本地时间等情况时，返回请求校验错误。
6. 预约时间的瞬间、原始 offset 和时区标识均保留在客户窗口陈述证据中；这仍是出差人陈述，不等同于系统独立核实客户。

## 后果

- API 字段结构不变，不需要数据库迁移或 OpenAPI 结构变更。
- 合法的夏令时切换窗口可使用不同的开始/结束 offset。
- 客户端应以所选 IANA 时区构造时间，而不是使用设备当前时区替代客户所在地时区。
- 回归测试覆盖合法 DST 跨越、冬季 offset 不匹配、DST 跳时段和结束时间 offset 不匹配。
