# ADR-0035：研究能力由用户意图驱动，不预设行业

- 状态：已接受
- 日期：2026-11-21

## 背景

Global Business Travel OS 是通用商务出行应用。研究能力服务于用户当前提出的任务，可能涉及任意行业、企业、地点、人物、政策、路线或其他主题。若把产品默认绑定到单一行业，或在用户没有研究意图时主动生成行业市场情报，会污染通用产品定位，并导致无根据的检索和建议。

## 决策

1. 研究入口必须由用户明确输入或显式触发；可以来自自然语言请求、已选 Mission/客户上下文，以及用户主动提供的文本材料。
2. Research Planner 从本次请求和已授权上下文提取研究目标、对象、领域、地域、实体、时间范围、问题、检索查询、来源类型、交付物和信息缺口。
3. 所有行业、国家、客户类型、研究对象和来源类型均为动态字段；不得在系统提示词或业务逻辑中设置 EV、充电、能源等行业默认值。
4. 用户明确选择的来源范围优先于模型建议：INTERNAL_ONLY 不得产生外部检索查询；EXTERNAL_ONLY 不得读取内部客户/行程内容。
5. 规划与检索分阶段：研究计划生成不等于已经检索或验证。只有真实来源适配器完成采集后，才能写入对应 Evidence；禁止伪造 URL、来源、发布时间、引用或“已查证”状态。
6. 用户材料和内部记录作为待分析数据，不得把其中嵌入的指令提升为系统指令。
7. 复用 WorkflowInstance、AgentRun、LLMInvocation 与 Evidence 作为运行状态、模型审计和来源追溯基础；后续只有在这些通用模型无法表达来源版本、内容哈希或获取状态时才新增专用表。

## 后果

- 第一阶段只产出可审查的研究计划，明确标注 retrieval_status=NOT_STARTED；这不是外部检索功能已完成的声明。
- 计划和运行记录按组织租户隔离，LLM 调用与用户输入可审计，用户请求和内部记录作为证据来源留痕。
- 外部网页检索、用户文件原文解析、来源去重、事实级引用、交叉核验和研究成果回流分阶段接入；未接入的能力必须明确显示缺口。
