# ADR-0013：签证案件与入境评估分离

- 状态：已接受（Accepted）
- 日期：2026-10-28
- 相关文件：迁移 `0018_visa_cases`、`app/models/visa.py`、`app/services/visa_service.py`、`app/api/routes/visa.py`
- 相关需求：PRD 方向二「AI 签证与跨境出行管家」

## 背景

现有的主动式签证提醒只生成"需核验"建议；PRD 要求进一步覆盖材料清单、申请进度、出发前检查。
如果把"外部要求"和"用户办理进度"放在同一张表，就无法区分"要求变了"和"用户状态没动"，
也无法审计要求来源与更新版本。

## 决策

1. 拆两张表：
   - `entry_assessments`：外部要求快照（来源、版本、置信度、是否需人工复核、评估时间）；
   - `visa_cases`：用户办理进度（国家、状态机、材料清单、提交/决定时间、护照有效期）。
2. 入境评估只读离线目录，措辞固定为"需人工复核"，不宣布签证结论；来源与版本必须随结果返回。
3. 签证案件状态机：`NEW → PREPARING → SUBMITTED → APPROVED/REJECTED`，任意非终态可
   `CANCELLED`；非法推进返回 409。
4. 一出行一国家一案件（唯一约束）；主动式签证建议批准时自动创建缺失案件并返回 case ids。
5. **不存护照号**，只可选保存 `passport_expires_at`，用于时效检查（PII 最小化）。

## 后果

- 好处：要求快照可刷新、办理进度可审计、重复提醒不会产生互相矛盾的案件。
- 代价：真实签证/入境数据源与预约渠道仍需外部集成；当前只做要求建模与进度管理。
