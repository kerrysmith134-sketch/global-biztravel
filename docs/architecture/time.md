# 时间语义：墙上时间、真实经过时间与夏令时

- 适用范围：规划引擎 `packages/planning-engine`、出行窗口、停靠时刻与验证器
- 相关测试：`packages/planning-engine/tests/test_dst.py`、`services/api/tests/test_dst_planning.py`
- 相关需求：设计文档第 6 章时间语义、N2「DST 跨日专项」

## 两类时间不能混用

| 语义 | 用途 | 运算方式 |
|---|---|---|
| **墙上时间** | 日界（00:00–23:59）、拜访时间窗、用户看到的日期与时刻 | 按本地日历比较；`enumerate_days` 用 `timezone_home` 切日 |
| **真实经过时间** | 航班/陆路时长、会议与服务时长 | 先转 UTC 相加，再转回原时区；`add_elapsed` / `elapsed_minutes` |

直接对带时区的 `datetime` 加 `timedelta` 是墙上时间运算。夏令时切换日会因此出错：

- 春季跳变日（如 Europe/Berlin 2026-03-29）：本地 02:00–03:00 不存在。01:30 加 60 分钟
  必须得到 03:30；墙上运算会得到不存在的 02:30。
- 秋季重叠日（2026-10-25）：本地 02:30 出现两次。第一次 02:30 加 60 分钟应得到第二次
  02:30（`fold=1`）；墙上运算会把两者之差算成 0。

## 日界与时长

- 一天按本地 00:00:00–23:59:59 切分。切换日仍是 1440 个**墙上分钟**，但真实经过时间是
  23 或 25 小时。`DayWindow.minutes` 返回墙上分钟，测试同时断言真实瞬时长度。
- 出行窗口首末日按实际起止时刻截断；中间日为完整本地日。
- 跨天位置连续：空日从最近一个有停靠的日子继续，找不到则回出发点。

## 独立验证

验证器的 `SERVICE_DURATION` 规则使用**自己的** UTC 差值实现，不导入调度器辅助函数；这样
调度器与验证器对"服务时长"的口径一致，但实现相互独立，符合不变量 I1。

## 边界

- 不处理"本地时间不存在"的用户输入（如把拜访窗口写进春季跳变缺口）。这种输入会按
  `fold=0` 解释；规划器不会替用户猜测意图。
- 签证工作日、每日打扰额度等业务按本地日历日计算，不使用真实小时数；它们不受 DST 影响。
